# KnitGrid

KnitGrid는 이미지를 업로드하거나 빈 격자에서 시작해 뜨개/비즈/패턴 도안을 만들고, 색상 코드와 진행 상황을 함께 관리하는 브라우저 기반 격자 편집기입니다. 현재 구현은 React + Vite 단일 페이지 앱이며, 서버 없이 배포해도 사용자의 브라우저 로컬 저장소에 작업을 저장하고 다시 열 수 있도록 설계되어 있습니다.

## 현재 제품 방향

- 첫 화면은 랜딩 페이지가 아니라 실제 편집 작업대입니다.
- 핵심 사용자는 도안을 직접 만들거나 이미지 초안을 격자로 변환한 뒤 손으로 다듬는 제작자입니다.
- 인터페이스는 큰 중앙 격자, 좌측 도구 레일, 우측 설정/팔레트/진행/가져오기 패널로 구성된 밀도 높은 작업형 UI입니다.
- 도안 데이터는 `paletteId`를 중심으로 관리합니다. 셀은 팔레트 항목을 참조하고, 팔레트 색상/코드/이름 변경은 기존 칠해진 셀에도 즉시 반영됩니다.
- 원본 업로드 이미지는 개인정보와 용량 문제 때문에 프로젝트 저장 데이터에 포함하지 않습니다. 적용 후 원본 비교 overlay는 현재 브라우저 세션에서만 유지됩니다.

## 기술 스택

- React 19
- Vite 8
- Tailwind CSS v4 (`@tailwindcss/vite`, `src/styles.css`의 `@apply` 중심)
- `lucide-react` 아이콘
- `image-q` 이미지 색상 양자화/디더링
- `jspdf` PDF export
- IndexedDB 직접 사용, 외부 DB/백엔드 없음

## 주요 파일

- `src/main.jsx`: 앱 전체 상태, 도안 편집 로직, 이미지 변환, 팔레트 편집, 로컬 프로젝트 저장, export 구현
- `src/styles.css`: Tailwind v4 기반 UI 스타일, 격자/모달/팔레트/로컬 프로젝트 목록 스타일
- `package.json`: Vite/React/Tailwind/image-q/jspdf 의존성

현재는 기능 대부분이 `src/main.jsx`에 모여 있습니다. 이후 규모가 커지면 팔레트, 격자 조작, 이미지 변환, 로컬 저장소를 모듈로 분리하는 것이 좋습니다.

## 편집 기능

### 격자

- 기본 크기: `48 x 64`
- 프리셋: `16 x 16`, `24 x 24`, `32 x 32`, `48 x 64`, `96 x 120`
- 커스텀 크기: 최대 `200 x 200`
- 행/열 번호 표시
- 우측/하단 번호 표시 토글
- 행 번호 방향:
  - 아래에서 위
  - 위에서 아래
- 보조선 간격:
  - 5칸
  - 10칸

### 격자 크기 변경 정책

그려진 셀이 하나라도 있는 상태에서 크기를 바꾸면 확인 모달이 뜹니다.

- `그림 유지`: 좌상단 기준으로 기존 셀을 보존합니다. 줄어든 영역의 오른쪽/아래 초과 셀은 잘립니다.
- `초기화`: rows/cols만 변경하고 셀은 비웁니다. 팔레트는 유지합니다.
- `취소`: 아무 상태도 변경하지 않습니다.

빈 격자 상태에서는 모달 없이 즉시 크기를 변경합니다.

### 도구

- 선택
- 화면 이동
- 펜
- 지우개
- 채우기
- 스포이드
- 좌우 반전
- 회전
- 반복 복제
- Undo / Redo

Undo/Redo는 셀 편집뿐 아니라 팔레트 변경, 팔레트 병합, 격자 구조 변경도 포함합니다.

### 격자 이동·스크롤

격자는 스크롤 컨테이너를 직접 움직입니다(도안이 화면 밖으로 밀려 되돌아올 수 없는 상태가 생기지 않습니다).

- 마우스: 행/열 번호 여백을 드래그하거나 `화면 이동` 도구로 아무 곳이나 드래그
- 터치(편집·진행 모드): 한 손가락 = 그리기(드래그하면 지나가는 칸을 이어서 칠함), 두 손가락 = 화면 이동, 번호 여백 한 손가락 드래그 = 스크롤
- 터치(미리보기·`화면 이동` 도구): 한 손가락 드래그가 그대로 스크롤
- 터치로 그릴 때 첫 칸은 손가락을 떼거나 움직인 뒤에 칠해집니다. 두 번째 손가락이 닿으면 예약된 칸은 칠하지 않고 화면 이동으로 전환합니다.

### 전체 도안 이동

우측 `격자 설정` 패널에서 도안 전체를 상/하/좌/우로 이동할 수 있습니다.

- 이동 칸 수: `1~200`
- 격자 밖으로 밀려난 셀은 삭제됩니다.
- 새로 생긴 영역은 빈 셀입니다.
- Undo/Redo 대상입니다.

### 행/열 추가 및 제거

행/열 추가 기준은 hover가 아니라 사용자가 클릭한 셀로 고정됩니다.

- 상태바의 현재 위치: hover 기준
- 행/열 삽입 기준: 마지막 클릭 셀 기준
- 기준 셀은 격자 위에 outline으로 표시됩니다.
- 지원 동작:
  - 기준 위 행 추가
  - 기준 아래 행 추가
  - 기준 왼쪽 열 추가
  - 기준 오른쪽 열 추가
  - 기준 위 행 제거
  - 기준 아래 행 제거
  - 기준 왼쪽 열 제거
  - 기준 오른쪽 열 제거
- 최대 `200 x 200`을 넘는 추가 버튼은 비활성화됩니다.
- 최소 1행/1열보다 작아지는 제거는 비활성화됩니다.
- Undo/Redo 대상입니다.

## 팔레트 / 컬러 코드

팔레트는 도안의 원본 색상표로 동작합니다.

기본 팔레트:

- `H7` 검정
- `H2` 아이보리
- `E15` 분홍
- `B4` 하늘
- `G9` 초록

### 팔레트 표시 모드

- 색상 + 코드
- 색상만
- 코드만

### 팔레트 편집

팔레트 행을 클릭하면 같은 패널 안에서 확장 편집 UI가 열립니다.

편집 가능 항목:

- 색상 picker
- HEX
- 코드
- 이름
- 기존 색상으로 병합
- 컬러코드 삭제
- 숨김/다시 표시

실 정보 필드는 제거되었습니다.

### 팔레트 동기화 정책

- 셀은 `paletteId`를 기준으로 팔레트 항목을 참조합니다.
- 셀 렌더링, 상태바, PNG/PDF export는 `paletteId`가 있으면 최신 팔레트 값을 우선 사용합니다.
- 팔레트 항목의 색상/코드/이름이 바뀌면 해당 `paletteId`를 가진 모든 셀의 `color/symbol/label`도 동기화합니다.
- JSON 저장 결과도 최신 팔레트 값이 반영된 셀 데이터를 포함합니다.

### 자동 병합

색상을 기존 팔레트 색상과 같은 HEX로 바꾸면 자동 병합합니다.

- source 팔레트 항목은 제거됩니다.
- source를 참조하던 셀은 target 팔레트로 재매핑됩니다.
- target 팔레트의 `id/code/name/color`가 승리합니다.
- source가 active palette였다면 active palette도 target으로 변경합니다.
- 병합 후 팔레트 패널에 안내 문구를 표시합니다.

### 숨김/다시 표시

팔레트 색상은 삭제하지 않고 도안에서 숨길 수 있습니다.

- 숨김 상태에서는 해당 색상을 참조하는 셀이 빈 칸처럼 보입니다.
- 같은 버튼이 `다시 표시` 동작으로 바뀝니다.
- 버튼 라벨과 아이콘으로 현재 상태를 명확히 보여줍니다.

### 삭제

컬러코드를 삭제할 수 있습니다.

- 사용 중인 컬러코드는 대체 색상을 선택해야 삭제됩니다.
- 사용 중이지 않은 컬러코드는 바로 삭제할 수 있습니다.
- 팔레트가 1개만 남은 상태에서는 삭제할 수 없습니다.

## 이미지 업로드 / 변환

이미지 업로드는 “일반 이미지의 격자 초안 생성”을 목표로 합니다. 구슬/비즈 중심을 의미적으로 인식해 행/열을 재구성하는 고급 인식 기능은 아직 범위 밖입니다.

### 변환 방식

이미지 모달에는 두 가지 변환 모드가 있습니다.

- `이미지 색상 자동 추출`: 기본값. 원본 이미지에서 주요 색상을 추출해 새 팔레트와 셀에 반영합니다.
- `현재 팔레트에 맞춤`: 기존 팔레트로만 매핑합니다. 색상 차이가 크면 경고와 source → target swatch를 보여줍니다.

### 이미지 후보 생성

이미지 업로드 후 한 가지 결과만 보여주지 않고 4개 후보를 생성합니다.

후보 예시:

- 선명
- 부드러움
- 디더링
- 단순화

각 후보는 다음 정보를 보여줍니다.

- 작은 thumbnail
- 색상 수
- 점수
- 품질 태그
- 주요 팔레트

`다시 생성` 버튼을 누르면 같은 이미지/설정으로 seed를 바꿔 후보를 다시 계산합니다.

### 맞춤/정렬 옵션

- 채우기: 격자를 꽉 채우고 넘치는 영역은 잘립니다.
- 맞춰 넣기: 이미지 전체를 보존하고 남는 칸은 여백이 됩니다.
- 늘려 맞춤: 잘림은 없지만 원본 비율이 왜곡될 수 있습니다.
- 가로 정렬: 좌측/중앙/우측
- 세로 정렬: 상단/중앙/하단

이미지가 격자보다 크거나 비율 차이가 큰 경우, 잘림/왜곡/디테일 손실 경고를 모달에 표시합니다.

### 원본 비교

이미지 변환 모달:

- 선택한 변환 후보 위에 원본 이미지를 반투명 overlay로 겹쳐볼 수 있습니다.
- 투명도 slider로 비교 강도를 조절합니다.

편집 화면:

- 변환 적용 후에도 현재 세션 동안 원본 이미지를 보존합니다.
- 변환 적용 직후 원본 overlay는 자동으로 켜지지 않습니다. 사용자가 `원본 보기`를 직접 켜야 보입니다.
- 중앙 격자 툴바에서 `원본 보기`, `원본 조정`, `투명도`, `크기`, `가로/세로 크기`, `이동`, `정렬 초기화`, `원본 제거`를 사용할 수 있습니다.
- 원본 이미지 안에 이미 격자가 있을 때 앱 격자와 맞출 수 있도록 셀 단위 이동, 균일 스케일, 가로/세로 분리 스케일을 제공합니다.
- `원본 조정`이 꺼져 있으면 overlay는 `pointer-events: none`이라 셀 편집을 방해하지 않습니다.
- `원본 조정`이 켜져 있으면 overlay를 직접 드래그해 위치를 조정할 수 있습니다.
- 적용 당시 rows/cols와 현재 rows/cols가 다르면 “원본 적용 당시 격자 기준” 안내를 표시합니다.
- 원본 overlay와 정렬값은 현재 세션 전용이며 JSON, IndexedDB, PNG/PDF export에 포함하지 않습니다.

## 진행 모드

`Progress` 탭에서 작업 중인 행을 추적할 수 있습니다.

- 현재 행 slider
- 현재 행 하이라이트
- 완료 행 토글
- 완료 행 수 표시

진행 상태는 현재 프로젝트 상태에 포함되지만, export에는 도안 결과 중심으로 반영됩니다.

## 내보내기 / 가져오기

### PNG

- 현재 도안 격자와 색상표를 PNG로 export합니다.
- 숨김 처리된 팔레트 색상은 도안에서 보이지 않습니다.
- 원본 overlay는 포함하지 않습니다.

### PDF

- `jspdf`를 동적 import해서 현재 도안 이미지를 PDF로 저장합니다.
- 원본 overlay는 포함하지 않습니다.

### JSON

기존 파일 기반 프로젝트 저장/열기 기능입니다.

- JSON 다운로드는 브라우저 파일 다운로드로 동작합니다.
- JSON 파일 열기는 로컬 프로젝트 ID가 없는 임시 작업으로 열립니다.
- JSON 파일을 열었다고 IndexedDB의 `내 작업` 목록에 자동 등록되지는 않습니다.
- 이후 사용자가 `로컬 저장`을 누르면 새 로컬 프로젝트로 저장됩니다.

## 로컬 프로젝트 저장소

배포된 사이트에서도 사용자가 브라우저 안에 작업 목록을 저장하고 다시 열 수 있도록 IndexedDB를 사용합니다.

### 저장소 정책

- DB name: `knitgrid-local`
- Store name: `projects`
- Key path: `id`
- Indexes:
  - `updatedAt`
  - `name`
- `localStorage`는 쓰지 않습니다. 큰 격자 데이터와 팔레트/프로젝트 메타를 감당하기 위해 IndexedDB를 사용합니다.
- 저장 데이터는 사용자의 브라우저/기기 단위입니다.
- 다른 사람, 다른 브라우저, 다른 기기와 자동 공유되지 않습니다.

### UI

상단과 가져오기/내보내기 패널에 다음 버튼이 있습니다.

- `새 작업`
- `내 작업`
- `로컬 저장`

상단에는 저장 상태도 표시합니다.

- 로컬 미저장
- 미저장
- 저장 중
- 저장됨
- 저장 오류

### 내 작업 모달

저장된 프로젝트 목록을 보여줍니다.

표시 정보:

- thumbnail
- 프로젝트명
- 수정일
- 크기
- 색상 수
- 칠해진 칸 수

지원 동작:

- 열기
- 복제
- 이름 변경
- 삭제

### 새 작업 정책

현재 작업이 있으면 바로 초기화하지 않고 확인 모달을 띄웁니다.

- 현재 작업 저장 후 새로 만들기
- 저장하지 않고 새로 만들기
- 취소

### 수동 저장

- 작업 변경사항은 자동 저장하지 않습니다.
- 사용자가 `로컬 저장` 또는 `현재 작업 저장 후 새로 만들기`를 눌렀을 때만 IndexedDB에 저장합니다.
- 새로 만든 임시 작업은 첫 `로컬 저장` 또는 `현재 작업 저장 후 새로 만들기`에서 ID가 생깁니다.
- 이미 저장된 로컬 프로젝트를 편집하면 상태가 `미저장`으로 바뀌고, 사용자가 다시 저장해야 반영됩니다.

### 로컬 저장 데이터

로컬 저장 record는 메타와 실제 프로젝트 데이터를 함께 가집니다.

메타:

- `id`
- `name`
- `createdAt`
- `updatedAt`
- `thumbnail`
- `summary`

`summary`:

- `rows`
- `cols`
- `colorCount`
- `paintedCells`

`projectData`:

- `version`
- `projectName`
- `rows`
- `cols`
- `palette`
- `grid`
- `activePaletteId`
- `displayMode`
- `rowDirection`
- `numberStart`

저장하지 않는 항목:

- 원본 업로드 이미지 object URL
- 원본 이미지 base64
- 이미지 변환 후보
- 현재 세션 전용 overlay 상태

## 데이터 모델 요약

### Palette item

```js
{
  id: 'h7',
  code: 'H7',
  name: '검정',
  color: '#1d2329',
  visible: true
}
```

### Cell

```js
{
  active: true,
  color: '#1d2329',
  symbol: 'H7',
  label: '검정',
  note: '',
  paletteId: 'h7'
}
```

`paletteId`가 있으면 렌더링/export는 팔레트의 최신 값을 우선 사용합니다. `color/symbol/label`은 JSON 호환성과 fallback을 위해 유지합니다.

### Project JSON

```js
{
  version: 2,
  projectName: '코지 파우치 패턴',
  rows: 64,
  cols: 48,
  palette: [],
  grid: [],
  activePaletteId: 'h7',
  displayMode: 'color-code',
  rowDirection: 'bottom-up',
  numberStart: 1
}
```

기존 `version: 1` 형태의 파일도 팔레트 normalize와 fallback 로직으로 최대한 그대로 로드합니다.

## 중요한 구현 포인트

- 수동 파일 수정은 `src/main.jsx`, `src/styles.css` 중심으로 이뤄졌습니다.
- 격자 표시 성능은 현재 일반 DOM button grid입니다. 최대 `200 x 200`에서는 DOM이 많아질 수 있습니다.
- 이미지 변환은 의미 인식이 아니라 픽셀 기반 색상 양자화입니다. 비즈/뜨개 도안의 원형 셀 중심을 자동 인식하는 기능은 아직 없습니다.
- 팔레트 변경은 도안 데이터에 영향을 주므로 Undo/Redo snapshot에 포함합니다.
- 로컬 저장은 IndexedDB 직접 API를 사용합니다. 외부 의존성은 추가하지 않았습니다.
- 다운로드 export는 브라우저에서 생성한 Blob/Data URL을 사용합니다.

## 수동 테스트 체크리스트

### 기본 편집

- 셀을 클릭해 칠하고 다시 클릭해 토글되는지 확인
- 지우개/채우기/스포이드가 동작하는지 확인
- Undo/Redo로 셀 편집이 복원되는지 확인

### 팔레트

- `H7` 색상을 바꾸면 기존 `H7` 셀 색이 즉시 바뀌는지 확인
- 코드/이름 변경이 셀 내부 코드 표시와 export에 반영되는지 확인
- `E15` 색상을 `H2`와 같은 HEX로 바꾸면 자동 병합되는지 확인
- 숨김 버튼을 누르면 도안에서 사라지고, 다시 누르면 표시되는지 확인
- 사용 중인 컬러코드 삭제 시 대체 색상 선택이 필요한지 확인

### 격자 구조

- 그림이 있는 상태에서 프리셋/커스텀 크기 변경 시 확인 모달이 뜨는지 확인
- `그림 유지`, `초기화`, `취소`가 각각 기대대로 동작하는지 확인
- 기준 셀을 클릭한 뒤 hover를 옮겨도 삽입 기준이 유지되는지 확인
- 위/아래/왼쪽/오른쪽 행열 추가와 제거가 Undo/Redo 되는지 확인

### 이미지 변환

- 이미지 업로드 시 4개 후보가 표시되는지 확인
- 후보 선택 시 큰 preview와 팔레트 preview가 바뀌는지 확인
- `다시 생성`이 새 후보를 계산하는지 확인
- 원본 겹쳐보기와 투명도 조절이 동작하는지 확인
- 적용 후 편집 화면에서 `원본 보기`가 자동으로 켜지지 않는지 확인
- `원본 보기`를 켠 뒤 균일 크기, 가로/세로 분리 크기, 셀 단위 이동, 드래그 조정, 정렬 초기화가 동작하는지 확인
- `원본 조정`을 끄면 셀 편집이 정상 동작하는지 확인
- PNG/PDF export에 원본 overlay가 포함되지 않는지 확인

### 로컬 프로젝트

- `로컬 저장` 후 `내 작업` 목록에 현재 작업이 나타나는지 확인
- 저장된 작업을 열면 grid/palette/name/settings가 복원되는지 확인
- 로컬 프로젝트를 연 뒤 셀을 수정해도 자동 저장되지 않고, `로컬 저장`을 눌러야 `미저장 -> 저장 중 -> 저장됨`으로 바뀌는지 확인
- 새로고침 후 `내 작업`에서 이전 작업을 다시 열 수 있는지 확인
- 복제/이름 변경/삭제가 목록과 IndexedDB에 반영되는지 확인
- JSON 파일 열기는 로컬 목록에 자동 등록되지 않는지 확인

## AI 작업 재개용 컨텍스트

새 AI 에이전트가 이 저장소를 다시 맡을 때는 먼저 아래를 확인하면 빠릅니다.

1. `README.md`의 제품/기능 정책을 읽습니다.
2. `src/main.jsx` 상단 constants와 helper를 확인합니다.
3. `function App()` 내부 state 목록을 보면 현재 기능 범위를 빠르게 파악할 수 있습니다.
4. 저장/로드 관련 흐름은 `serializeCurrentProject`, `applyProjectData`, `saveCurrentLocalProject`, `loadProject`를 중심으로 봅니다.
5. 이미지 변환은 `IMAGE_CANDIDATE_CONFIGS`, `buildImageConversionCandidates`, `applyImageDraft`를 중심으로 봅니다.
6. 팔레트 정책은 `resolveCellDisplay`, `syncCellsForPaletteChange`, `mergePaletteItems`, `updatePaletteItem`, `deletePaletteItem`, `togglePaletteVisibility`를 중심으로 봅니다.
7. 스타일은 `src/styles.css`의 component class 이름과 JSX class 이름이 직접 대응됩니다.
